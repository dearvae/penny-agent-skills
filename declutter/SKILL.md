# declutter：把照片里的杂物清掉，别的一点不动

一批照片，逐张清掉散落的杂物，出对照图给人眼验收。
**它不是修图、不是美化、不是摆家具。** 它做的事等于「有人进屋把地上的东西收走了，然后在同一个位置用同一台相机重拍了一张」。

这条线的价值全在「可信」上：处理过的照片如果让人觉得和现场不一样，就比不处理更糟。
所以红线一节是这个技能的主体，不是附录。

## 前提（每次开工先核对，缺「必须」就停下来先补）

| | 项目 | 怎么确认 |
|---|---|---|
| 必须 | Node 18 以上 | `node --version` 出版本号（脚本零 npm 依赖，不用 npm install；照片本身仍然会发往你选的那家官方 API，见红线 9） |
| 必须 | 用户自己的图像模型 key，写在他工作文件夹的 `.env.image` 里 | `cat .env.image` 看到 `GEMINI_API_KEY=` 后面有值。没有就照 `.env.image.example` 里的两条链接去申请，**我们不提供 key、不代付费、不走任何中转** |
| 必须 | 付费层已开通 | Google：图片输出不在免费额度里，要在 https://aistudio.google.com/projects 绑卡升付费层。OpenAI：要充预付余额，还可能要过组织验证 |
| 必须 | 一个照片文件夹，jpg / jpeg / png / webp | `ls` 看到图。HEIC 先转：`sips -s format jpeg x.heic --out x.jpg`（macOS 自带，不用装东西） |
| 必须 | 用户本人逐张过目对照图 | 这一步不能由我代替，也不能跳。见红线 6 |
| 必须 | **业主 / 客户知道这些照片要送去 AI 处理** | 每张照片的完整文件会上传到 Google 或 OpenAI 的服务器（用户自己账号下）。这是这个技能唯一的对外数据流。画面里有人、有信件文件、有门牌单元号的更要先问过。不确定就别跑。见红线 9 |
| 可选 | Chrome（`/Applications/Google Chrome.app`） | 有就自动拼对照图；没有就只出 HTML，让用户自己打开截图 |
| 可选 | 场景 | 默认 `--scene residential`（住宅空间照）。商铺 / 办公室 / 厂房用 `--scene commercial`；二手物品出货照用 `--scene item` 并用 `--item` 点名要卖的东西 |
| 可选 | 走哪家 | 默认 Google（`gemini-3.1-flash-image`）。**两家都锁不住原图的像素尺寸**（见「常见卡点」最后一条）：OpenAI 只是更贴近原始长宽比，代价是门槛更高（要充预付余额、可能要过组织验证） |

## 红线（先读，全程有效）

1. **只动杂物。** 可以清掉的只有这几类：地上散落的物品（箱子、袋子、鞋、玩具、纸张、电线、插排）、外露的电线和充电线、垃圾桶 / 脏衣篮 / 水桶 / 拖把 / 扫把 / 清洁用品、桌面台面柜面的杂物（碗碟、瓶子、食物、文件、遥控器、纸巾盒）、晾着或搭着的衣服毛巾、宠物碗 / 猫砂盆 / 宠物窝 / 宠物玩具、挡住镜头的人（含摄影者倒影）和停在画面里的车与自行车。**这个清单之外的任何东西都不动。**

2. **不改结构。** 墙、门、窗、窗框、地板和地板材质、天花、踢脚线、内嵌橱柜、衣柜、厨具、卫浴洁具、房间尺寸、房间形状和布局，一律保持原样。不裁切、不旋转、不校正倾斜、不改机位和透视。**判断不了一件东西是散落杂物还是房子的固定部分，就留着别动。**

3. **不抹缺陷。** 裂缝、水渍、潮湿印、发霉、剥漆起泡、锈、污渍、磕角、划痕、破损瓷砖、外露管道、磨损的表面，处理后必须还清楚看得见。**抹掉缺陷是误导买家**——这是这个技能唯一会真正害到人的地方，也是 CEA 会找上门的地方。原图里能看见的缺陷，处理后看不见了 → 这张作废，用原图。

4. **不加不存在的东西。** 不摆家具、不铺地毯、不加绿植挂画摆件、不换地板、不重新刷墙、不加窗外景观、不改天气 / 时间 / 采光、不做 HDR、不调色、不改白平衡和曝光锐度。**要摆家具是 virtual staging，不是这条线的事，直接告诉用户我们不做。**

5. **原图永远保留，绝不覆盖。** 所有产出写到 `<原文件夹>/去杂物_<日期>/` 下的新文件夹。任何情况下不写回原文件、不删原文件、不改原文件名。处理坏了就是从原图重新来。

6. **交付前必须由用户本人逐张看对照图。** 我不替他判断「够不够像」。他看完点头才算完成。他没看就想直接上传 → 告诉他这一步不能省。

7. **处理过的照片上挂牌前要按平台规矩标注。** 截至 **2026-09-17**，我们没有拿到 PropertyGuru 和 99.co 关于 edited photo 的逐字成文条款，所以口径是：**上传前去平台自己的照片规定页面看一眼当时怎么要求标注，按那个办。**（PropertyGuru 挂牌规则在它的 agent 后台 / help center；99.co 同理。）
   可以确定的上位规则是 CEA 的《Practice Guidelines on Ethical Advertising》那条底线：广告里的照片必须是**这套房本身**的真实照片，不得造成误导。
   规则和平台要求都会变，**上传之前对一眼官网**。

8. **不代上传到挂牌平台 / 不代发送。** 不上传到 PropertyGuru / 99.co、不发 WhatsApp、不发邮件、不发社媒。我只把图和报告放进文件夹，上挂牌和发送永远是用户自己在自己的 App 里做。

9. **照片会被上传到 AI 供应商，这件事必须先说。** 每一张照片的完整文件会发到用户自己账号下的 Google（`generativelanguage.googleapis.com`）或 OpenAI（`api.openai.com`）官方端点做处理——**这是这个技能唯一的对外数据流**，脚本说「零第三方依赖」指的只是不装 npm 包，不是照片不出机器。
   房源内景照本身就带别人的个人资料：桌上的信件文件、画面里的业主 / 租客 / 摄影者本人、墙上的家庭照、门牌单元号、窗外的车牌。这些是业主的资料，用户只是受托拍摄。**开跑前要让业主 / 客户知道照片要送去 AI 处理；不确定就别跑。** 画面里有人、有信件、有门牌号的，先跟业主确认，或者先自己裁掉 / 换一张再跑。
   两家供应商各自的数据保留和滥用审查政策以他们当时的条款为准，规则会变，要跟业主解释就去官网对一眼，别替供应商担保。

10. **key 是用户自己的。** 只从他电脑上的 `.env.image` 读，脚本里没有任何默认 key、默认账号、中转地址、代付费入口。读不到就打印去哪申请然后退出，绝不回落。

11. **不碰合同、不碰 LOI、不给法律意见。** 用户问「这样处理会不会违规」→ 只复述红线 3 和红线 7 的事实和出处，让他自己判断或去问 CEA / 他的经纪行合规。

## 第 1 步：先问清四件事，再动手

用户丢来一个文件夹就想跑，先确认这四件（他一次说全就不用问）：

1. **这些照片是谁拍的、是不是这套房本身的照片。** 不是他的房 / 不是这套房 → 停，红线 7 的上位规则就挂在这里。
2. **业主 / 客户知不知道这些照片要送去 AI 处理。** 每张照片的完整文件会上传到他自己账号下的 Google 或 OpenAI 服务器，这是这个技能唯一的对外数据流。画面里有人、有信件文件、有门牌单元号的，先跟业主确认，或者先自己裁掉 / 换一张再跑。他说不确定 → 停，先去问业主。见红线 9。
3. **有几张、他想先试几张。** 超过 10 张一律先跑 `--limit 3` 试水，看过对照图再跑整批。一张一张地烧钱试比整批返工便宜。
4. **这是什么照片、有没有特别想清掉或特别不许动的东西。**
   - 住宅 / 房间空间照 → 默认，什么都不用加。
   - 商铺 / 办公室 / 厂房仓库 → `--scene commercial`（商品、货架、设备、招牌、菜单不动）。
   - 二手物品出货照 → `--scene item --item "画面中间那辆灰色折叠自行车"`，**必须问清哪个是要卖的东西**，不然默认场景会把那辆自行车、那个纸箱、那套碗碟当杂物清掉。
   - 「阳台的晒衣架是固定的别拆」「桌上那盆花留着」这种保护型的话不用写进 `--prompt-extra`——硬禁止里已经写死「分不清是杂物还是固定部分就留着别动」。`--prompt-extra` 只用来写限定型的一句：「只清掉地上左侧那三个纸箱，其他一切不动」。

顺手把 HEIC 挑出来（两家都不一定吃）：
```
cd <照片文件夹> && for f in *.[Hh][Ee][Ii][Cc]; do sips -s format jpeg "$f" --out "${f%.*}.jpg"; done
```

## 第 2 步：核 key 和花钱，跑 dry-run

`--dry-run` 不调 API、不要 key、不花钱，只列出会处理哪些文件、输出什么尺寸、花多少钱。**每次开工先跑这个**，把数字报给用户，他点头才真跑。

```
node <skill目录>/scripts/declutter.mjs "<照片文件夹>" --dry-run
```

钱的口径（截至 **2026-09-17**，出处 https://ai.google.dev/gemini-api/docs/pricing）：
- `gemini-3.1-flash-image` 官方 per-image：0.5K **$0.045**、1K **$0.067**、2K **$0.101**、4K **$0.151**
- 更便宜：`gemini-3.1-flash-lite-image` 1K 约 **$0.0336**；更好：`gemini-3-pro-image` 1K/2K **$0.134**
- OpenAI 那条线：官方**只公布 token 费率**（图像输出 $30/1M token），**没有 per-image 价目表**。所以脚本不给 openai 的钱数估算，只教用户跑一张看 `usage.output_tokens` 自己乘。网上流传的「$0.05 一张」「$0.21 一张」全是第三方测算，别当准数报给用户。

**价格和免费额度会变，跑大批之前对一眼官网。** 20 张 2K 约 $2，先按这个量级给用户一个心理价位。

## 第 3 步：跑

```
# 默认（Google，2K）
node <skill目录>/scripts/declutter.mjs "<照片文件夹>"

# 先试 3 张
node <skill目录>/scripts/declutter.mjs "<照片文件夹>" --limit 3

# 商铺 / 办公室 / 厂房仓库（商品、货架、设备、招牌不动）
node <skill目录>/scripts/declutter.mjs "<照片文件夹>" --scene commercial

# 二手物品出货照（--item 必填：要卖的那件东西一个像素都不动）
node <skill目录>/scripts/declutter.mjs "<照片文件夹>" --scene item --item "画面中间那辆灰色折叠自行车"

# 带一句限定（只能写「只清掉哪几样」；出现「修 / 补 / 调亮 / 摆家具 / 地毯 / 绿植 / crack / brighten / staging」
# 这类字样脚本直接退出，不下发也不处理——红线 3 和红线 4 不能用这个参数绕开。
# 三条硬禁止一直留在 prompt 里，但模型会被后面更具体的指令带偏，所以这道闸做在脚本里，
# 不靠一句 prompt 措辞守；每次实际下发的 prompt 原文也会抄进 报告.md 的「运行记录」留痕）
node <skill目录>/scripts/declutter.mjs "<照片文件夹>" --prompt-extra "只清掉地上左侧那三个纸箱，其他一切不动"

# 换 OpenAI（更贴近原始长宽比，但同样锁不住原图的像素尺寸；门槛更高）
node <skill目录>/scripts/declutter.mjs "<照片文件夹>" --provider openai

# 补跑失败的那几张（点名；写回同一个 去杂物_<日期>/，报告按原文件名合并，不覆盖整批台账）
node <skill目录>/scripts/declutter.mjs "<照片文件夹>" --only 06_书房.jpg,09_厨房.jpg

# 已经跑完了，只想重做对照图
node <skill目录>/scripts/declutter.mjs "<照片文件夹>" --compare-only
```

脚本逐张处理、逐张打印进度，**单张失败不中断整批**，失败原因写进报告。

**一次成型，不要连续改同一张。** 两家都是整图重绘而不是像素级修补：每改一轮，没被编辑的区域都会轻微漂移、画质轻微衰减。第一轮不满意 → **从原图重新跑**，别拿处理后的图再改一遍。

## 第 4 步：逐张验收（这一步不能代替用户做）

打开 `对照/` 里的每一张，按这个顺序看，任何一条不过就弃用这张、用原图：

1. **结构有没有变**：墙线、门窗位置和形状、地板花纹和拼缝走向、天花、橱柜门、踢脚线。地板花纹变了是最常见的翻车点。
2. **缺陷还在不在**：原图里的裂缝、水渍、发霉、剥漆、锈、破损，处理后必须还看得见。
   **这一条不能只看对照图**：对照图每栏 1800 物理像素，iPhone 的 4032px 原图压到这个宽度是 2 倍多的下采样，一条发丝裂缝在上面几乎看不见。查缺陷要直接打开 `处理后/` 里的输出图和原图，各自按 100% 实际像素逐处比对（两张尺寸不一样，看的是同一处细节还在不在）。对照图只用来看整体有没有跑偏（结构、构图、光、多出来的东西）。
3. **有没有多出东西**：新家具、新地毯、新绿植、新挂画、窗外多出来的树或楼、变亮的光。
4. **家具有没有挪位或变形**：沙发、床、餐桌的位置和形状要和原图对得上。
5. **该清的清干净了吗**：还留着一半的杂物、留下糊掉的一块，也算不过。

跑完把结果原话交给用户，**不要替他说「效果很好」**：

> 跑完了，成功 N 张、失败 M 张。产出在 `去杂物_<日期>/`，原图一张没动。
> 你现在要做的：打开 `对照/` 逐张看，除了杂物以外任何一处不一样（地板花纹、少了一条裂缝、窗外多了东西、光变亮了、家具挪位）就弃用那张，直接用原图。
> 缺陷必须还在——原图里的裂缝水渍发霉，处理后还得看得见，看不见了这张就作废。这一条要开 `处理后/` 里的输出图和原图，各自按 100% 实际像素比，对照图看不出发丝裂缝。
> 要上挂牌的话，上传前去 PropertyGuru / 99.co 看一眼它当时对处理过的照片怎么要求标注，按那个办。

## 输出格式

全部写到 `<原文件夹>/去杂物_<YYYY-MM-DD>/`，原文件夹里的原图一个字节不动：

```
<照片文件夹>/
├── 客厅.jpg                    ← 原图，不动
├── 卧室.jpg                    ← 原图，不动
└── 去杂物_2026-09-17/
    ├── 处理后/
    │   ├── 客厅.jpg            ← 文件名和原图一致，方便一眼对上
    │   └── 卧室.jpg
    ├── 对照/
    │   ├── 客厅_对照.png       ← 左「原图 BEFORE」右「处理后 AFTER」，同高并排
    │   └── 卧室_对照.png
    └── 报告.md
```

**对照图**：白底，两栏并排，每栏 900 CSS px 等比缩放，截图带 `--force-device-scale-factor=2`，所以 png 上每栏是 **1800 物理像素**（4:3 横图整张 3696×1598，3:4 竖图 3696×2648，本机实测）；左栏灰底标题条「原图 BEFORE」，右栏浅绿底标题条「处理后 AFTER」；底部小字写原文件名 + 「只去杂物：结构、缺陷、采光应完全一致。发现任何一处不一致就弃用这张，用原图。」+ 一句「查缺陷要开输出图按 100% 实际像素比对」。不依赖 ImageMagick / PIL，用本地 HTML + 本机 Chrome `--headless=new --screenshot` 截出来；没有 Chrome 就只留 HTML，报告里写明让用户自己打开截图。

**报告.md** 字段定死（补跑会**合并**写回同一份，不覆盖）：

| 段 | 内容 |
|---|---|
| 头 | 跑的时间、原文件夹、走的模型和档位（含 `input_fidelity`）、场景（`--scene` / `--item`）、**额外指令（`--prompt-extra`）原文或「无」**、成功 / 失败张数、**照片上传到了哪个官方端点**、一句「原图未被改动」 |

## 中介场景（只在用户是房产中介时加这一节）

其余行业用上面的流程就够了，只要选对场景：餐厅 / 店铺 / 办公室出租 / 厂房走 `--scene commercial`，二手平台出货照走 `--scene item --item "<要卖的东西>"`，Airbnb 和自住房照走默认。中介多四件事：

1. **上挂牌前的标注**，见红线 7。这是中介独有的合规面。
2. **对照图不是给客户看的**。它是给中介自己验收的内部物料。给客户 / 挂牌只放 `处理后/` 里的图，或者原图。
3. **跟 pg-cobroke 的客户版房源卡怎么接**：用户说「用处理后的图做客户版」→ 先确认他已经逐张看过对照图，再把 `处理后/` 的路径交给 pg-cobroke 那条线，本技能不做房源卡。
4. **别对客户说「我修过图」以外更多的话**。处理过就是处理过，标注清楚比解释漂亮更安全。

## 常见卡点

**现象：脚本一上来就报「没读到 GEMINI_API_KEY」**
原因：`.env.image` 不在脚本找的三个位置（`--env` 指定的 → 当前工作目录 → 照片文件夹），或者文件在但变量名写错 / 后面是空的。
怎么解：在**当前终端所在的目录**建 `.env.image`，一行 `GEMINI_API_KEY=你的key`，注意变量名全大写、等号两边不要空格、不要引号。或者直接 `--env /完整/路径/.env.image`。key 去 https://aistudio.google.com/apikey 申请。

**现象：报 HTTP 400 `API key not valid`，或 403 / 429**
原因：400 通常是 key 复制时带了空格换行，或复制的是别的项目的 key。403 / 429 通常是**没绑卡升付费层**——Google 的图片输出不在免费额度里，OpenAI 还可能是组织验证没过。
怎么解：400 重新复制一遍 key。403 / 429 去 https://aistudio.google.com/projects 点 Set up billing 绑卡（OpenAI 是充预付余额 + https://platform.openai.com/settings/organization/general 走 Verify Organization）。OpenAI 的组织验证要政府签发证件，卡住了就换 `--provider google`，这就是默认推荐 Google 的原因。

**现象：处理后地板花纹变了 / 窗外多了棵树 / 少了一条裂缝**
原因：两家都是**整图重绘**而不是像素级修补，官方定位就是「理解原图后重画」，未编辑区域必然有漂移。prompt 只能压小概率，压不到零。
怎么解：**这张作废，用原图**，别试图再修一轮（多轮只会更糟）。想救就从原图重跑一次，或者把 `--prompt-extra` 写具体（「只清掉地上左侧那三个纸箱，其他一切不动」）。要求「像素级只动一小块」的，目前两家都做不到确定性，这是技能的能力边界，跟用户讲清楚，别承诺。

**现象：对照图没出来，只有一堆 .html**
原因：本机没有 `/Applications/Google Chrome.app`，或 Chrome 截图那一步失败。
怎么解：双击那些 `.html` 自己看 / 自己截图，验收效果是一样的。想要 png 就装 Chrome 再跑 `--compare-only` 补。

**现象：HEIC 的图被跳过了**
原因：iPhone 直出的 HEIC / HEIF 两家都不一定吃，脚本不猜，直接列出来让你先转。
怎么解：跑脚本打印的那条 `sips` 命令（macOS 自带，不用装东西），转完再跑一次。

**现象：输出图的尺寸和原图不一样**
原因：**两家都给不了原图的精确像素尺寸，这是能力边界，不是配置问题。** Gemini 只能给「比例档位 + 尺寸档位」（1:1 / 4:3 / 16:9… + 0.5K/1K/2K/4K），长宽比不在档位里的会被套到最近的比例，构图轻微变化。OpenAI 那条线是「宽高都要 16 的倍数 + 总像素在 655,360~8,294,400（约 0.66MP~8.29MP）之间 + 单边 ≤3840 + 比例夹在 1:3~3:1」，四条叠起来的结果是：手机 / 相机直出的 12MP 图**一定**被缩到约 8.2MP。实测 4032x3024 → 3312x2480（缩了 18%）、3024x4032 → 2480x3312、1700x1000 → 1696x1008、6000x4000 → 3520x2352、800x600 → 944x704（反而被放大）。只有原图本身宽高就是 16 的倍数、总像素又正好在区间里（比如 2048x1536），输出才会刚好相等。
怎么解：能接受就接受（挂牌平台上传后自己还会再压一次）。`--provider openai` 只是换一种圆整方式、更贴近原始长宽比，不是「锁尺寸」——别拿这个理由让用户去过 OpenAI 的组织验证和充值。要严格等于原图像素尺寸：两家都给不了，跟用户说清楚。报告里每张会写它被改尺寸的真实原因（总像素上限 / 下限 / 16 的倍数圆整 / 长宽比被夹）。

**现象：脚本说「--prompt-extra 里出现了「修」，这一句不下发，整批不跑」，直接退出**
原因：`--prompt-extra` 是自由文本，直接拼在 prompt 最后一段，而图像模型对更靠后、更具体的指令命中率更高——一句「把裂缝补一下」是真能把红线 3 压下去的。所以脚本对这个参数做了关键词硬拦截（修 / 补 / 抹 / 刷墙 / 调亮 / 调色 / 裂缝 / 水渍 / 霉 / 锈 / 摆家具 / 地毯 / 绿植 / crack / defect / brighten / hdr / staging / furniture / rug / plant …），命中就退出，没有「警告后继续」这一档。
怎么解：看清他到底想干什么。想保护某样东西 → 不用写，硬禁止里已经写死「分不清就留着别动」（「刚装修过」「晒衣架是 fixed」这类说法不会被拦）。想限定范围 → 改成「只清掉地上左侧那三个纸箱，其他一切不动」。真要修缺陷 / 摆家具 / 调色 → 直接说不做，那是另一类产品、另一套合规要求。**不要为了绕过拦截去改脚本或改词。**

**现象：用户说「顺便帮我摆点家具 / 把裂缝补一下 / 调亮一点」**
原因：这三件分别是 virtual staging、抹缺陷、美化调色，全部在红线 2 / 3 / 4 里。
怎么解：直接说不做，说清为什么：抹缺陷会误导买家，摆家具和调色是另一类产品、另一套合规要求。不要因为用户坚持就绕开红线，也不要用 `--prompt-extra` 塞进去——真塞了脚本也会拦掉退出，并且每次实际下发的 prompt 原文都抄在 报告.md 的「运行记录」里，留痕。

**现象：补跑一张之后，不确定 报告.md 里其他几张的记录还在不在**
原因：报告是这条线的交付物和合规台账（每张的偏差说明、CEA 底线、标注要求都在里面），所以补跑是**合并**不是覆盖：脚本跑完先读回已有的 报告.md，按原文件名合并表格行再写回，并在「运行记录」追加一段。`--only` 还会沿用同一个文件夹下最近的 `去杂物_*`，429 隔一天才补跑也不会另建一个新日期的文件夹，产出不会被劈成两处。
怎么解：打开 报告.md 看「## 运行记录」有几段——每跑一次一段，带那次实际下发的完整 prompt。要是表里的行真的少了，说明手上那份脚本是旧版本，换成当前版本再补跑，别在旧版本上补。
