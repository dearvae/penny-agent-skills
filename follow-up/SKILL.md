# follow-up：客户跟进消息草稿

一次只解决一件事：这个客户现在这个状态，下一条消息该怎么说。
出三条口气不同的草稿，你挑一条、自己改、自己发。

## 前提（每次开工先核对，缺「必须」就停下来先补）

| | 项目 | 怎么确认 |
|---|---|---|
| 必须 | 客户在哪个阶段 | 对照第 1 步的阶段表报一个；说不清就把上次对话经过讲三句，我来定位 |
| 必须 | 上次对话要点 | 三样：什么时候聊的、他说过的**原话或顾虑**、你答应过他什么。翻一下聊天记录，三句也够 |
| 必须 | `我的档案/跟进口气.md` 存在 | 工作文件夹里有这个文件；没有就先跑第 0 步 |
| 必须 | 渠道 | 默认 WhatsApp。是邮件 / 微信 / 小红书私信要说，长度和格式不一样 |
| 可选 | 有没有**真的**新信息 | 新房源、新政策、价格变动、他上次问的问题你查到了——有就写进草稿 A；编不出来就走第 2 步的「没有新信息怎么办」 |
| 可选 | 上次跟进的日期和第几次了 | 对照「间隔表」看这次该不该发。没记就报个大概 |
| 可选 | 客户的语言偏好 | 他平时用英文还是中文回你；不确定就跟你的档案走 |
| 可选 | 客户怎么称呼 | 只要称呼（Mr Tan / 陈姐 / C 先生），**不要全名、不要电话、不要地址** |

## 红线（先读，全程有效）

1. **不发送。** 这条 skill 只产草稿。不拼 `wa.me` 链接、不开 WhatsApp、不用浏览器或 computer-use 去点发送、不代发邮件短信。用户自己复制到自己的 App 里发。他说「你直接帮我发」也不发，回一句：草稿给你，发送你自己来。
2. **不编数字，也不编房源属性。** 市场价、成交价、租金、涨幅、空置率、「这个区今年涨了 X%」——不是用户自己给的、或他自己查到并给了出处的，一个字都不写进草稿。**房子本身的说法同样算数**：面积、朝向、楼层、楼龄、装修、家具、租约状态、离地铁几分钟、格局——用户没给的一个字都不写，也不许用「差不多」「应该」「一般都是」「同一栋楼所以」补上（同一栋楼不同 stack 的面积能差十几平米）。查不到、没给，就把那句话删掉，或改成「我把资料发你」——把核对这件事挪回他手上，不要替他断言。凡草稿里出现数字，输出块里必须跟一行**出处 + 截至日期**，并提醒他发之前对一眼官网（税率和规则会变）。别用「据说」「听说市场上」糊过去。
3. **不逼单。** 这些话一律不写：「最后一套」「今天不定就没了」「已经有人在谈了」「明天要涨价」「给你留到今晚」「错过就没有了」「我只能帮你到这里」。制造稀缺和时间压力的句式，即使是真的，也由用户自己决定要不要说——不是我替他写进去。
4. **不连发。** 一个客户一天只出一条可发的草稿。三条草稿是**让他挑一条**，不是三条都发；输出里要写明这句。下一次跟进的时间按「间隔表」给，不是「明天再问一次」。
5. **客户资料只留在他自己的电脑。** 客户全名、电话、门牌 / 单元号、具体地址、项目名、金额、家庭情况不写进 `我的档案/跟进口气.md`（那个文件只存他的**语言习惯**），不上传任何地方，不写进示例、不写进任何要给第三方看的文件。要在文件里指代客户就用「C 先生」「客户 A」。
   **这条管到 `原话样本` 那一节。** 他贴进来的真实消息里带的往往就是单元号、报价、「你太太说的那个预算」「小孩下半年入学」——名字去掉了照样认得出是谁。所以样本必须先换成占位符再落盘（换法见第 0 步），换完才写文件。这个文件是全流程里唯一强制落盘、而且每次跟进都会被读回上下文、还可能被备份或同步走的文件，所以它必须是最干净的那个。
6. **不碰合同、不碰 LOI、不做法律意见。** 客户在草稿里问到条款、违约、税务怎么算，草稿里只写「这个我帮你问清楚再回你」，具体条款让他走正规文件流程。
7. **不替客户做决定。** 不写「我建议你买」「这个值得投」。草稿的立场是给信息、约时间、问一个问题。
8. **CEA 禁语一个字不写进草稿。** 跟进消息一旦带上某个盘、某个区，就是他本人署名发出去的营销沟通——CEA 广告规矩和广告法都管得到。四类一律不写：
   - **收益承诺**：「稳赚」「保值增值」「肯定涨」「回报 X%」「长期看一定升」「买了不会亏」。
   - **绝对化用语**：「最便宜」「最好」「唯一」「第一」「顶级」「全岛最」「这个区最便宜」。
   - **「学区房」**：新加坡是 1 公里内优先抽签、不是划片直升，只能写「在 X 小学 1 公里内」。
   - **金融敏感词**：「零首付」「垫资」「贷款包过」「保证批」「帮你做高评估」。

   这条专门补红线 2 和红线 7 漏掉的那一格：「这套长期保值」既没有数字（红线 2 管不到）、也不是「我建议你买」（红线 7 管不到），但它是收益承诺，归这条管。用户口头让你写进去也不写，回一句：这句是 CEA 广告规矩的雷，草稿里我不写；你要说就自己在 App 里加，那是你的执业风险。

## 第 0 步：首次用先学他的口气

跟进消息最容易露馅的地方是口气。第一次用这条 skill（每个用户一次），先问：

> 「你平时跟进客户是怎么发的？把你最近真发过的**两条**贴给我（中英文都行）。
> 贴之前先把这几样换成占位符，我要的是你的句式，不是客户是谁：
> **名字 → Mr X ｜ 电话 → `<电话>` ｜ 门牌 / 单元号 / 具体地址 → `<单元>` ｜ 项目 / 小区名 → `<项目>` ｜ 任何金额 → `<价格>` ｜ 家庭情况（小孩入学、太太的预算）→ `<家庭情况>`**
> 换完贴过来。我照你的口气写，以后都这么写。」

他贴过来带真实资料的（很常见，因为是复制粘贴），**不要直接存**：自己先替换成占位符，替换完把改动告诉他一句（「你贴的两条里有单元号和报价，我换成 `<单元>` 和 `<价格>` 才存的」），然后存的是替换后的版本。

他贴了就抽这几样，存到工作文件夹 `我的档案/跟进口气.md`：

| 抽什么 | 记成什么样 |
|---|---|
| 语言 | 全英 / 全中 / 中英混（混的话记清哪些词他习惯用英文，如 viewing、unit、offer） |
| 称呼 | Hi + 名 / Mr + 姓 / 陈姐 / 直接开口不打招呼 |
| 自称 | Jasmine here / 我是 X / 不自称 |
| 长短 | 一般几句、一句几个字、会不会分段 |
| 开头习惯 | 直接说事 / 先寒暄一句 / 先道歉（Sorry to disturb） |
| 结尾习惯 | Thanks / Let me know / 有问题随时问我 / 不收尾直接结束 |
| emoji | 用不用、用哪几个、放哪（句尾 / 不用 / 只用 🙏） |
| 标点 | 用不用句号、会不会全小写、会不会连发好几个短句 |
| 他不会说的话 | 从样本里看出来的：不用感叹号 / 从不叫「亲」/ 不说「机会难得」 |

文件结构最多三节，每节顶上照抄它的硬规矩：

- **`原话样本`** —— 硬规矩：**本节只许出现占位符**（Mr X / `<电话>` / `<单元>` / `<项目>` / `<价格>` / `<家庭情况>`）；出现真实客户信息就删掉那句重写。存档前自己扫一遍这七类字段：人名、电话、门牌和单元号、具体地址、项目 / 小区名、金额、小孩入学和家庭情况。而且只留够看出句式的**最短版本**——一条五句的消息抽两句就够，不要「留着以后方便看」。
- **`抽出来的特征`** —— 上面那张表填好。这节才是这个文件真正的产出；`原话样本` 只是它的依据。
- **`他改过的措辞`** —— 一开始空着。

**更稳的做法，默认就这么做**：特征抽完就把 `原话样本` 那节删掉，只留 `抽出来的特征` 和 `他改过的措辞`——原话看完即弃，写草稿时只读特征表就够了。用户明确说「样本留着，我想自己对照」才留，留的也必须是上面那个占位符版。

他说「没有，你看着写」就用默认骨架——短句、不寒暄、不 emoji、结尾一句 Let me know——但出完第一批草稿让他改，**他改过的那版存进档案当样本**——存之前照上面那张对照表过一遍占位符（他改的那版里大概带着项目名和报价）。

之后每次写草稿：先读这个文件。他在挑草稿时改了措辞，把改法追加到「他改过的措辞」那节（写成「他把 Just checking in 改成 Quick update」这种对照）。他说「换个口气」「重新学一遍」才重问。

## 第 1 步：定位阶段（先说他在想什么，再写字）

写错口气多半是阶段判断错了。先对照这张表报一个阶段给用户确认（一句话：「按你说的，他现在是『说要再想想』这个阶段，对吧」），他点头再写。

| 阶段 | 客户此刻在想什么 | 这次跟进的目的 | **不能说什么** |
|---|---|---|---|
| S1 刚留资没回话 | 不记得自己留过、或同时留了好几家、或只是随手看看 | 让他知道你是谁、你能帮什么，把门留着 | 不要「你之前咨询过我们的产品」这种客服话；不要一上来问预算；不要连着追问 |
| S2 体验过没表态（看过 / 试用过 / 听过方案） | 有点兴趣但没到要决定；也可能已经否掉了只是不好说 | 拿一个明确的反馈，好还是不好都行 | 不要问「感觉怎么样？」（等于逼他表态）；不要假设他喜欢；不要直接推下一个 |
| S3 说要再想想 | 真在想 / 在等家人朋友的意见 / 钱还没到位 / 客气地拒绝 | 找出**卡在哪一环**，不是催他想完 | 不要问「想好了吗」；不要设期限；不要把「再想想」当成 yes |
| S4 嫌贵 | 要么真超预算，要么觉得不值这个价——这是两件事 | 分清是预算问题还是价值问题，然后按那一边给东西 | 不要马上降价或暗示能降；不要说「这个价很值」；不要拿别人的成交价压他 |
| S5 在比别家 | 在收集报价 / 在比人；说出来通常是想让你出条件 | 说清你这边不一样在哪（服务、信息、速度），让他愿意回来问你一句 | 不要贬同行、不要点名说别家；不要问「他们报多少」；不要承诺「我给你最低」 |
| S6 报价 / 提案被拒 | 有点没面子、怕再来一次又被拒 | 让他知道被拒不等于结束，下一步是什么 | 不要复盘他哪里做错了；不要马上劝他加钱；不要说「我早说了」 |
| S7 成交后维护 | 这事已经办完了，你来找我干嘛 | 做完最后一件有用的事，留一个以后能自然联系的理由 | 不要立刻要转介绍；不要群发式的节日祝福；不要推下一单 |

阶段选不出来（比如他既嫌贵又在比别家）：**按他最近一句话的情绪选**——最后一句是价格就走 S4，最后一句是「我再看看别家」就走 S5。别两个都写。

房产特有的阶段（租客续约、卖家挂久没动静）见下面「中介场景」。

## 第 2 步：写三条草稿（三条轴，不是三种说法）

三条必须是三种**不同的动作**。写完自查：能不能一句话说出这三条各自在干什么？说不出就是没写够。

**草稿 A · 给理由**——因为有新东西所以找你。
骨架：一句真实的新信息 → 它和他的关系一句 → 不要求他做任何事收尾。
新信息可以是：新出的选择、他上次问的问题你查到了答案、公开的政策 / 数据变动（必须标出处和截至日期）、时间节点到了（他自己说过的那个时间）。
**没有新信息怎么办**：不许编。按这个顺序找替代——① 他上次问过、你当时没答上来的那个问题；② 他自己说过的时间点到了（「你说三月看，三月到了」）；③ 一件你替他做完的小事（帮他把三个选择整理成一张表）。三条都没有，就**不出草稿 A**，明确告诉用户：这次没有找他的理由，建议按间隔表往后推，或者先去做出一个理由来。

**草稿 B · 给台阶**——不催，给一个不回也不尴尬的出口。
骨架：把主动权还给他 → 一句明确的出口（不回 = 默认某个状态）→ 不留问题。
出口句长这样：「如果计划变了就跟我说一声，我先不打扰」「你不回我就当先放着，需要的时候直接找我」「不用回我，我这边先按你上次说的记着」。
这条的效果是让他没有回复压力,所以**一个问号都不要有**，也不要「方便的时候回我一下」这种伪出口。

**草稿 C · 给行动**——一个具体的小请求，小到十秒能完成。
只有两种形态，选一种：① **是非题**（「你要的还是三房，还是可以看 3+1？一句 yes / no 就行」）；② **约十分钟**（给两个具体时间段让他选，不要问「你什么时候方便」）。
请求必须只有一个。两个问题就变成问卷，客户就不回了。

三条共同的硬规矩：照档案里的口气写（语言、称呼、长短、结尾、emoji）；每条独立成立，不依赖另外两条；长度不超过他平时的 1.5 倍；不出现红线里的任何一句。

## 第 3 步：交付 + 记回档案

按下面的「输出格式」输出，然后说三句：
1. 「三条挑一条，自己改完自己发。」
2. 「下一次跟进：〔日期区间〕。再没回就〔停 / 转季度问候〕。」
3. 「草稿里有数字的，发之前对一眼官网——规则和税率会变。」

他改了措辞或说「这条不像我」，追加到 `我的档案/跟进口气.md` 的「他改过的措辞」节，下一次就按新的写。

## 输出格式

固定这个样子，一次一个客户：

```
客户：<称呼> · 阶段：<S 几 + 阶段名> · 第 <N> 次跟进 · 距上次 <X> 天
他在想什么：<一句>
这次要拿到的：<一句>

──────── 草稿 A · 给理由 ────────
<消息正文，可直接复制，不带引号不带说明>

为什么这么写：<一句>
用到的新信息：<是什么> ｜ 出处：<哪来的> ｜ 截至：<日期>

──────── 草稿 B · 给台阶 ────────
<消息正文>

为什么这么写：<一句>

──────── 草稿 C · 给行动 ────────
<消息正文>

为什么这么写：<一句>
请求是：<是非题 / 约十分钟>

────────────────────────────
挑一条发，别三条都发。
下一次跟进：<日期区间> ｜ 再没回：<停 / 降频 / 转季度问候>
自检：□ 没有未标出处的数字  □ 草稿里每个关于房子的说法都能指回用户给的那句话  □ 无 CEA 禁语（收益承诺 / 绝对化 / 学区房 / 金融敏感词）  □ 没有逼单话术  □ 长度和他平时一样  □ 称呼对  □ 没替客户做决定
```

没有新信息时，草稿 A 的位置写：`草稿 A · 给理由 —— 这次没有真实的理由可用，不出。建议：<按第 2 步给的三条替代>`。

## 间隔表（隔多久跟一次、几次没回就停）

「没回」= 完全没回复。他回了一句（哪怕是「在忙」）就不算没回，重新计次。

| 阶段 | 首次跟进 | 之后间隔 | 最多几次 | 停了之后 |
|---|---|---|---|---|
| S1 刚留资没回话 | 留资当天（越快越好，最好 1 小时内） | 第 2 天 → 第 7 天 | 3 次 | 停。转季度问候（有真信息才发） |
| S2 体验过没表态 | 24–48 小时内 | 4 天 → 10 天 | 3 次 | 停。转季度问候 |
| S3 说要再想想 | 按他说的时间点；他没说就 5 天 | 10 天 → 三周 | 3 次 | 停。转季度问候 |
| S4 嫌贵 | 3 天（给他消化的时间） | 一周 → 三周 | 3 次 | 停。有符合他预算的新选择再联系 |
| S5 在比别家 | 2 天 | 一周 → 两周 | 3 次 | 停。别追问结果 |
| S6 报价被拒 | 当天或第 2 天（趁热，但不复盘） | 一周 → 三周 | 3 次 | 停。有新选择再联系 |
| S7 成交后维护 | 交割 / 交付后一周 | 一个月 → 三个月 → 之后每季度 | 不设上限，但每次都要有由头 | 无由头就不发 |

跨阶段的总闸：**同一个客户一周最多两条**，一天最多一条。两个阶段的计数不叠加——阶段变了（比如从 S3 变成 S4），次数从 1 重新算。

**这张表自己必须对得上，改表先算两个等式**（现在七行都过）：
1. `首次 1 条 + 「之后间隔」的步数 = 「最多几次」`。S1 = 1 + 2 = 3 ✓，S2–S6 同理；S7 不设上限，不参与这条。
2. 把节奏排成天数，**任意 7 天窗口内不超过 2 条**。S1 = 第 0 天、第 2 天（第 1 周 2 条）、第 7 天（第 2 周 1 条）✓。

两个等式里的任何一个对不上，就是表错了，不是执行的人错了——照表发会直接踩爆总闸。

## 中介场景（房产特有的）

主体那张表对任何销售都成立。房产多两个阶段，另外几个阶段的读法也不一样。

**多出来的两个阶段：**

| 阶段 | 客户此刻在想什么 | 这次跟进的目的 | **不能说什么** |
|---|---|---|---|
| S8 租客到期前续约 | 还没决定续不续；可能在看别的房；怕一续就涨租 | 拿到续 / 不续的意向，给双方留出时间 | 不要先替房东开涨价的口；不要说「不续就要搬」；不要在还没谈之前给具体涨幅 |
| S9 卖家挂了很久没动静 | 觉得是中介不行、或价格就是不肯降 | 把「市场怎么反应」讲清楚，让他自己看到下一步选项 | 不要直接说「你的价太高」；不要拿邻居的成交价拍他；不要承诺「降 X 万就能卖掉」 |

S8 的间隔：到期前 90 天第一次，到期前 60 天第二次，到期前 45 天第三次；三次没回就直接写一条给房东（不是给租客）说明情况。S9 的间隔：每两周一次带上真实反馈（看房组数、收到的反价、挂盘数据），没有新反馈就不发。

**其它阶段在房产里的读法：**
- S2 体验过没表态 = **看过房没表态**。看房当天晚上不发（他还在跟家里人说）；第二天白天发。草稿 A 的新信息优先用同项目 / 同地段的新挂盘，其次是他看房时问过但你当场没答的那个问题（楼龄、维修费、租约状态）。
- S4 嫌贵 = psf 谈不下来 / 租金超预算。先分清是**总价不够**还是**觉得不值**：总价不够就往下调条件（面积、楼龄、楼层、地段边缘），觉得不值就补信息（同类在挂的、楼盘实际状况）。**成交价和 psf 一律来自他自己查到的官方数据**（URA 的私宅成交、HDB 的转售成交，或他自己的挂盘系统），草稿里必须带出处和截至日期，并提醒他发之前对一眼官网。
- S5 在比别家 = 在比其它中介 / 在比几个经纪行。只说你这边能给什么（能约到哪些盘、多久出方案、cobroke 的范围），不评价同行，不问他别家给了什么条件。
- S6 报价被拒 = offer 被卖家 / 房东拒了。当天可以发一条，但只说下一步（要不要再调、还有哪两套在看），不复盘、不劝加价。
- S7 成交后维护 = 交房后。第一次跟进就做一件实事（水电煤 / 网络 / 搬家 / 装修联系人，他需要哪样给哪样），**不在这一条里要转介绍**。
- 涉及印花税（BSD / ABSD / SSD）、贷款额度（TDSR / LTV）、CPF 这类数字：草稿里能不写就不写；一定要写就只写「规则我发你官方链接」，具体数字让他自己在官网核，并在输出块里写清出处和截至日期 + 一句「税率和规则会变，用之前对一眼官网」。
- 合同、LOI、TA 条款、违约、法律责任：草稿里只答「我帮你问清楚再回你」。

## 常见卡点

**现象：三条草稿读起来差不多，像同一句话换词。**
原因：信息太少（用户只给了「客户没回」三个字），或者没按三条轴写，A 里也带了问题、C 也在给理由。
怎么解：回到前提表补「上次对话要点」，至少要有他的一句原话。然后逐条验：A 里有没有一条新信息？B 里有没有问号（有就是错的）？C 里是不是只有一个请求？三条里有两条能互换位置，就是没写够。

**现象：用户说「太客气了」「不像我发的」「我不会这么说话」。**
原因：档案样本不够（只贴了一条、或贴的是很正式的那条），或者抽特征时抽错了重点。
怎么解：让他重贴三条**最近真发过**的（要包含一条他随手发的、不正式的），**贴之前照第 0 步把名字、电话、单元号、地址、项目名、金额、家庭情况换成占位符**；重抽特征，覆盖 `我的档案/跟进口气.md` 的特征节。他直接改草稿的，就把他改后的那版当新样本存进去——他改的比他说的准；存之前一样过一遍占位符（他改的那版里大概带着项目名和报价）。

**现象：没有任何新信息，草稿 A 写不出来，又不想空着。**
原因：这个客户的跟进理由已经用完了——这是节奏问题，不是文案问题。
怎么解：按第 2 步的三条替代找（他没答上的问题 / 他自己说过的时间点 / 你替他做完的一件小事）。都没有就**不出 A**，并按间隔表把这次跟进往后推。不要用「just checking in」硬凑，那条消息发出去的唯一效果是提醒他删掉你。

**现象：客户一直不回，用户想加频率、想换个更强的说法。**
原因：把「不回」当成没看到。绝大多数不回是「现在不想」，加频率只会把「现在不想」变成「以后也不想」。
怎么解：照间隔表把次数走完（各阶段 3 次），第 3 次就用草稿 B 的口气收尾——给一个明确的出口，然后停。想做点什么就换渠道（他在小红书私信过你就回那边）或者换由头，别换力度。停掉的客户进「季度问候」名单，有真信息才发。

**现象：用户把客户的全名、电话、预算、家庭情况都发过来，问要不要存起来方便下次。**
原因：跟进档案存的是**他自己的口气**，不是客户库。
怎么解：`我的档案/跟进口气.md` 里只存语言习惯，客户一律写成「C 先生」「客户 A」。客户资料留在他自己原来的地方（他的 CRM 或他自己的记录），这条 skill 不落盘、不外传、不写进任何示例文件。下次跟进他重新贴三句上次对话要点就够了。

**现象：档案里的 `原话样本` 节翻开一看，全是单元号、报价、「他太太说预算 4,200」「小孩明年一年级」。**
原因：第 0 步让他贴真发过的消息，他复制粘贴过来，而这条 skill 每次跟进都会把这个文件读回上下文——等于把客户资料长期落在一个会被反复读取、还可能被备份 / 同步 / 打包分发的文件里。红线 5 说「不落客户资料」，这个文件恰恰是全流程唯一强制落盘的，所以它是第一个要查的地方，不是最后一个。
怎么解：当场清。逐句把七类字段换成占位符（人名 → Mr X，电话 → `<电话>`，门牌 / 单元号 / 地址 → `<单元>`，项目名 → `<项目>`，金额 → `<价格>`，家庭情况 → `<家庭情况>`），换不动的整句删掉——特征已经抽出来了，原话本身没有保留价值。清完告诉他清了什么。以后按第 0 步默认做法走：特征抽完就把 `原话样本` 整节删掉。

**现象：用户说「你直接帮我发出去」「帮我拼个 WhatsApp 链接」。**
原因：他觉得省事。
怎么解：不做。回一句：「草稿在这里，你复制到 WhatsApp 发。发送这一步我不碰——谁发的谁负责，也不会替你发错人。」然后把草稿排版成方便一键复制的样子（每条一个独立代码块），这就是能帮的极限。
