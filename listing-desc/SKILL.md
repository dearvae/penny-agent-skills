# listing-desc：一份房源资料，出一整套挂牌文案

挂牌框里那段字是买家/租客第一眼看到的东西。写得好的不是形容词多的，是**每一句都能指回资料里某一行**的。
这条 skill 只做一件事：把你手上的资料整理成可以直接粘贴的 headline + description（短 / 标准 / 长几个长度），另附一张对照表让你 30 秒核完。

不联网、不开浏览器、不用任何账号或 API key。**没有资料就没有内容**——这是本 skill 的全部脾气。

业主自己挂、房东挂租盘、中介挂自己拿到授权的盘，流程一样。
**但开工第一句先确认归属和授权**——别人的盘只给收料清单，不给可粘贴正文。见下面「第 0 步之前」。
中介专属的东西集中在最后一节。

## 前提（每次开工先核对，缺「必须」就停下来先补）

| | 项目 | 怎么确认 |
|---|---|---|
| 必须 | **归属与授权**：这套房是不是你自己（或你所属经纪行）拿到业主 / 房东书面授权在挂的 | 见「第 0 步之前：第一句必须问」。**每套新房源问一次，不沿用上一套的答案** |
| 必须 | **一份房源资料**（最少要有：卖盘还是租盘 + 项目名或大概位置 + 房型 + 面积 + 报价） | 用户贴进对话，或指一个文件/截图。这四项缺任何一项都按第 0 步一次问齐，不要开始写 |
| 必须 | **发到哪几个渠道**（PG / 99.co / 自己网站 / 落地页 / 小红书 / 客户群） | 决定出几版、要不要挂 CEA 信息（见「执业信息按渠道」那张附表和「输出格式」第 6 节） |
| 可选 | 楼层段、朝向、景观 | 资料里有就照抄；没有就整篇不出现这三样，不猜 |
| 可选 | 楼龄 / TOP 年份 / 地契（freehold 或 99-year） | 从用户给的资料或他发来的项目页截图里抄。他手上没有就整篇不写年份和地契，并在「还缺的」里列出来，让他自己去 PropertyGuru 项目页核完补给你。**本 skill 不联网，不替他查** |
| 可选 | 装修情况和年份 | 「大概 2020 左右」不算有，见「不许写的话」 |
| 可选 | 家具（租盘几乎必须）：fully / partially / unfurnished，带清单更好 | 租盘没这项就先问，这是租客第一个问题 |
| 可选 | 地铁站名 + 步行分钟（谁量的） | 「自己走过 X 分钟」可用；「应该挺近」不可用。线路代号（EW6 这类）和 District 编号同理，用户没给就不写 |
| 可选 | 1 公里内小学（名字 + 距离 + 谁量的） | 没量过就不写学校，一个字都不写 |
| 可选 | 小区设施清单 | 从用户给的资料或项目页截图里抄，写清单不写形容词。他没给就不写设施，列进「还缺的」让他自己去项目页抄一份来 |
| 可选 | 租约状态：卖盘 vacant / tenanted till 几时；租盘几时可入住 | 买家和租客都会先看这个，能拿到就拿 |
| 可选 | 业主自己最满意的一两条（住了几年的真话） | 往往是全文最有说服力的一句，问一句就有。**但要引述业主的话，先问他同不同意写进公开文案**（见红线 5） |
| 可选 | 中介姓名 + CEA 注册号 + 经纪行名称 + 经纪行 licence number | 只在要发自己网站 / 落地页 / 小红书 / 客户群时用得上，见「执业信息按渠道」那张附表。业主自挂不需要 |

本 skill 不需要装任何东西，也不读任何 `.env`。要用到别的外部服务的时候是走别的技能，不在这里。

## 红线（先读，全程有效）

0. **先确认这套房你有权挂。** 没确认是他自己（或他经纪行）拿到业主授权在挂的盘，就不出任何可粘贴正文——只出收料清单和骨架。替没有 marketing authority 的人写房源广告是 CEA 层面的越界；把别家中介挂牌页上的文案改写一遍发出去，也是拿人家花钱写的东西。每套新房源确认一次，不许沿用上一套的答案。
1. **不许写这套房没有的东西。** 资料里没有的事实、你没核实过的数字、凭「同小区一般都这样」推出来的结论，一律不写。宁可短，不可编。写完逐句问一遍「这句在资料里哪一行」，指不出来的删掉。**MRT 线路代号和 District 编号也算数字**——用户没给就不写，别凭记忆填。
2. **单元级的东西只能来自资料。** 楼层、朝向、景观、装修、家具、租约状态——这些是这一套房的事，不许从房型和面积反推，也不许用「通常」「一般」补。见第 2 步的三级表。
3. **不承诺回报。** `guaranteed`、`assured returns`、「稳赚」「保值增值」「肯定涨」「回报 X%」、en-bloc 预测，全部不写。投资角度只摆可核实的数字（报价、面积、psf）。
4. **不碰歧视字眼。** 种族、国籍、宗教、家庭结构的筛选（含 "suitable for local family only" 这类委婉说法）一个字都不能出现，租盘尤其高发。租客筛选是业主在看房和 TA 阶段自己做的事。
5. **不写单元号、不写门牌号、不写业主任何个人信息、不写业主为什么卖。** 位置只到路名或「off 某条路」。
   「不写个人信息」不等于「不写名字就行」：房源广告带着地址，业主就是可识别的那个人。所以业主的**性别**（he / she / 他）、**自住还是投租**、**正在搬走 / 家具带走 / 换房**这类处境，一个都不进正文，统一只写 `the owner`。
   要引述业主的原话（「最满意的是晚上安静」这种），**先问业主同不同意把这句写进公开挂牌文案**，把他的答复和日期记进「还缺的」。没拿到同意就整句删掉，不许改写成「据说」「听说」绕过去。
6. **不碰合同、不碰 LOI、不做法律和税务意见。** 押金、租期条款、佣金、交易条件都不进 description，那是 TA / LOI 阶段的事。最多写业主明确说过的偏好（例 `min 2-year lease preferred`）。
7. **涉及钱和税的数字要有出处和「截至日期」。** 报价和租金照资料抄并注明是用户提供的、截至哪天；psf 是你算的就写算式；市场行情、印花税、物业费、月供如果非要写，必须标出处和截至日期，并在交付时说一句「税率和规则会变，用之前对一眼官网」。拿不准就不写——description 不是算账工具。
8. **只出草稿，不代挂、不代发。** 粘贴到 PropertyGuru / 99.co 后台、点发布、发给客户，全部是用户自己在自己的账号里做。本 skill 不生成任何发送链接、不预填任何发送框、不替用户点任何按钮。

### 附表：执业信息按渠道

**CEA 广告规矩要求的执业信息按渠道处理，不是一刀切。** 持证中介发的房源文案，不管发在哪，都是 property advertisement。

| 渠道 | 正文里写不写执业信息 | 为什么 |
|---|---|---|
| PropertyGuru / 99.co 的 description 正文 | **不重复写。** 平台的中介信息块已经印了姓名、经纪行、`CEA: Rxxxxxxx / Lxxxxxxx` | 这条豁免**只适用于有固定栏位、平台代印的挂牌平台**。栏位里的信息是不是对的，用户自己去后台核 |
| 自己网站 / 落地页 / 小红书 / 朋友圈 / 客户群 | **文案末尾必须带四项 + 电话**：中介姓名、Salesperson Registration Number、经纪行名称、Estate Agent Licence Number，加上 CEA 登记的联络电话 | 这些地方没有平台代印的那个块。CEA《Practice Guidelines on Ethical Advertising》PG 2/2011 §2.1 / §3.6 把 online advertising、website posting、social media 都算进来，要求这几项随广告出现，并带 "Salesperson Registration Number" / "CEA Registration Number" 这类字样（依据：CEA PG 2/2011，截至 2026-09；规矩会改，正式发布前对一眼 cea.gov.sg） |
| 业主自己挂 / 房东自己挂 | 不适用，不写 | 他不是持证中介，这条规矩不管他 |

四项缺哪一项就在「还缺的」里点名要，别自己编、别留空占位。
小红书那版即使挂了这四项，**电话、微信号、二维码照旧不放**（平台规矩，见第 3 步）——所以小红书版按用户自己的合规做法处理：要么放姓名 + 注册号 + 经纪行 + 执照号，要么这条盘不发小红书。

## 第 0 步之前：第一句必须问（不许跳，不许记答案）

拿到房源资料，**在写任何正文之前**先问这一句，原话可以照抄：

> 先确认一件事：**这套房是你自己在挂的吗？**（你或你所属经纪行拿到业主 / 房东的书面授权）
> 是 → 我直接给你可以粘贴的几版文案。
> 不是 → 我只给你「要问业主哪几项」的收料清单和一份骨架，不出可粘贴正文——替没有授权的人写房源广告，CEA 那边是越界；照着别家中介的挂牌文案改写一遍，也是拿人家花钱写的东西。

判断只有两档，不留中间地带：

| 他怎么回 | 算哪种 | 做什么 |
|---|---|---|
| 「我自己挂的」「我的盘」「业主签了授权给我」 | 有授权 | 走 **A 线**：照常出全部版本 |
| 「同事的」「co-broke 的」「客户群里转来的」「网上看到的」「业主还没签」 | 没授权 | 走 **B 线**：只出收料清单 + 骨架，不出可粘贴正文 |
| 不回答、绕开、「差不多算我的」「我有他口头同意」 | 没授权 | 走 **B 线**，并把原因说一遍 |

- **每套新房源问一次。** 上一套他说「是我的」，不代表这一套也是。一次会话里丢三套就问三次。
- co-broke 想要文案：让**挂盘那位中介**自己跑这条 skill，或者让他把业主的授权书转过来。
- B 线的骨架里所有 `{}` 槽位一律留空，不替他填任何一条事实——那些事实本来就不是他手上的。

## 第 0 步：收料（缺的一次问齐，不要挤牙膏）

先看用户给的料，按上面前提表逐项对。缺的**一次列全问**，一条消息问完，不要一问一答来回五轮。问法就是列清单：

> 这几项我这里是空的，你补一下我就开始写（不知道的写「不知道」，我就整篇不提它）：
> 1. **这套房是你自己在挂的吗**（你或你经纪行拿到业主授权）？每套新房源我都要问一次，上一套的答案不算。
> 2. 楼层段（low / mid / high floor，不要具体层数）
> 3. 朝向和窗外看到什么
> 4. 装修：哪年、动了哪些部分
> 5. 家具：空屋 / 部分 / 全配（租盘请列清单）
> 6. 地铁站名 + 步行几分钟（你自己走过还是估的）。**线路代号和 District 编号你手上有就给，没有我就不写**，不凭记忆填
> 7. 楼龄 / TOP 年份 / 地契、小区设施清单——你资料里有或有项目页截图就给我；没有我整篇不写，我不联网也不替你查
> 8. 1 公里内小学：哪几所、多远、在哪量的
> 9. 租约状态：卖盘是空屋还是带租约到几时；租盘几时可入住
> 10. 业主住了这几年最满意的一两条。**如果要把他的原话写进文案，先问过他同不同意公开**（哪天问的也告诉我）
> 11. 这段要发哪几个渠道（PG / 99.co / 自己网站 / 落地页 / 小红书 / 客户群）
> 12. 只有要发自己网站 / 落地页 / 小红书 / 客户群时才要：你的姓名、CEA 注册号、经纪行名称、经纪行 licence number、CEA 登记电话

用户说「不知道」「别写了」的项目就整篇不提，**不要用形容词把空洞填上**。
「1,109 sqft 的三房应该有个 utility room 吧」——这就是编，问一句而已。

料齐了先自己算两件事，写进对照表备用：
- **psf**：报价 ÷ 面积，四舍五入到整数。例 `1,880,000 ÷ 1,109 = S$1,695 psf`。租盘算 `月租 ÷ 面积`（惯例写月租，psf 可不写）
- **面积口径**：公寓用 strata area；有 built-up / land area 之分的（landed）分开写清楚，别混

## 第 1 步：定卖盘还是租盘（决定骨架和侧重）

| | 卖盘 | 租盘 |
|---|---|---|
| 读者关心的第一件事 | 价钱和 psf 值不值、能不能马上住 | 几时能入住、家具到什么程度、通勤多久 |
| 必须写清楚 | vacant possession 还是 tenanted till 几时 | available from 哪天、furnishing 三档哪一档 |
| 侧重 | layout 和面积效率、地契和 TOP、1km 小学（量过才写）、小区氛围 | 拎包入住程度、到上班地点的通勤、超市和吃饭、租期偏好 |
| 不要写 | 回报率、印花税、en-bloc | 押金、代理费、TA 条款 |

用户没说是卖还是租就问一句，别猜——两套骨架的重心完全不同。

## 第 2 步：给每条事实定级（本 skill 的核心纪律）

写之前把手上每条事实按「说的是小区、说的是户型、还是说的是这一套房」分三级。这一步决定哪句能写、怎么写。

| 级别 | 说的是什么 | 素材只能从哪来 | 怎么写 |
|---|---|---|---|
| **小区级** | 项目名、TOP 年份、地契、开发商、设施清单、MRT 距离、商场巴刹、主干道 | 用户给的资料、用户发来的项目页截图、用户自己知道的、用户量过的。**本 skill 不联网，没有第五个来源** | **可以写**，但每条要用户点头。说不准的降级成不带数字的说法，或者删掉。线路代号、District 编号、TOP 年份这类用户没给的，一律不写，列进「还缺的」让他自己去项目页核 |
| **户型级** | `squarish layout`、`dumbbell layout`、`no wasted corridor`、`utility room`、`balcony`、`enclosed kitchen` | 只能来自用户看过这套房、或有平面图 | **用户没确认就不写。** 凭房数 + 面积推 layout 是编。确认不了又想说一句，就写 `efficient layout` 这种不含具体承诺的，或者干脆不写 |
| **单元级** | 楼层段、朝向、景观、西晒、装修年份和范围、家具、租约状态、报价 | **只能来自资料** | 资料没给就一个字不写。这是整条 skill 最硬的一条——别的单元的卖点不是你这套的卖点 |

**「不许写这套房没有的东西」的操作版**：写完一句，手指着资料指出那一行。指不到就删。
最常犯的三个错：把同小区别的单元的景观写成这套的、把 3 房默认配成 2 卫、把「小区有泳池」写成「泳池景」。

## 第 3 步：英文怎么写（这段是写法规范，照着来）

**英文为主。** 新加坡挂牌的默认语言是英文，买家、租客、同行都在用英文搜。中文版只在用户明确要（自己网站、小红书、客户群）时另出一版，不替代英文版。

语言规矩：
- **短句。一行一个事实。** 不写长定语从句，不写一句话套三个卖点。手机上一屏能扫完才有人读
- **英式拼写**：`neighbourhood`、`metres`、`favourite`、`realise`。新加坡本地惯例
- **本地术语原词照用**，不要翻译也不要解释：`sqft`、`psf`、`MRT`、`HDB`、`condo`、`strata`、`freehold` / `99-year leasehold`、`TOP 2016`、`mid floor`、`north-facing`、`fully / partially / unfurnished`、`vacant possession`、`tenanted till`、`utility room`、`A&A`
- **数字格式**：`S$1,880,000`、`S$1,695 psf`、`1,109 sqft`、`7 mins' walk`。价格带逗号，币种写 `S$` 不写 `SGD` 不写裸数字
- **一个具体数字顶五个形容词。** `7 mins' walk to Kembangan MRT` 有用，`excellent connectivity` 没用
- **删掉这些空词**：`amazing`、`stunning`、`must see`、`once in a lifetime`、`dream home`、`priced to sell`、`cosy`（在挂牌语境里等于「小」，买家看得懂）、`TLC needed`
- **格式**：分段小标题可以全大写（`THE UNIT`、`LOCATION`），正文不要全大写、不要连串叹号。emoji 标准版一个都不放，长版最多 1–2 个
- **PG / 99.co 那两版：不放联系方式、不放外部链接、不放别的平台名**。平台会退回或降权，电话号码还会被 PG 直接 mask 掉
- **自己网站 / 落地页 / 小红书 / 客户群那几版**：按「执业信息按渠道」那张附表处理——持证中介必须挂姓名 + CEA 注册号 + 经纪行 + 执照号 + 登记电话；小红书版不放电话、微信号、二维码

## 第 4 步：写各版本（该出的都出，不问用户要哪版）

各版的事实完全一致，只是能塞多少。**不许为了写长而加内容，也不许为了写短而改事实。**

PropertyGuru / 99.co 的后台只有**两个文本栏位：headline 和 description**，没有第三个「摘要」栏位。所以：

### Headline — 挂牌页的标题栏位（PG / 99.co 都必填）

PropertyGuru 公布的硬规则，按这个写，否则后台会退（依据：PropertyGuru AgentNet「Requirements for Headlines」，截至 2026-09；平台规则会改，以后台提示为准）：

- 长度 **10–70 个字符**（不是词，是字符，空格也算）。写完数一遍，把字符数标出来
- 只许用 `a-z` `A-Z` `0-9`、空格，和这些符号：`$ , " - . ! : ; & / ? @ % ( ) #`
  - **`·` 不在允许集里**，别用。分隔符用 `-`
- 最多 **2 个连续标点**
- **连续数字不超过 6 位**（被符号或空格隔开的也算）。所以写 `S$1.88M`，不写 `S$1,880,000`
- **只有首字母大写**（缩写词例外：`3BR`、`MRT`、`TOP`、`BBQ`）。不许整句全大写
- 不放联系方式（电话会被 mask 掉）

模板和例子：

```
{项目名} - {房型} {面积}sf - {一到两个最强卖点}
Eastbourne Grove - 3BR 1,109sf - Renovated, Mid Floor, Vacant   ← 61 字符
```

### 短转发句 — WhatsApp / 客户群 / 朋友圈转发用的一句话

- 1–3 句，**35–60 个英文词**，不用 bullet、不用换行（转发时换行经常被吃掉）
- 顺序：最强的一个卖点 → 房型 + 面积 → 位置 + 通勤 → 状态 → 报价
- 这版**不是**给 PG 后台用的，PG 那边只填 headline 和 description 两栏。它的用处是用户自己在 WhatsApp 里粘一句就发
- 他自己发，本 skill 不生成任何发送链接、不预填任何发送框

### 标准版 — 主 description，这是主力

**120–200 词**，短行 + bullet，手机上两屏内读完。

**出几个标准版看渠道数**（这条定死，别每次跑出来不一样）：

- 只挂 1 个平台 → **只出一个标准版**，平台备注表就一行，不要提「标准版 B」
- 挂 2 个或更多平台（PG + 99.co 是常态）→ **按平台出 A/B**：`标准版 A（PropertyGuru）`、`标准版 B（99.co）`。事实逐条一致，只换 HOOK、段落顺序、同义词，做法见「中介场景」那节
- 再多平台就 C、D，同一个规则

骨架定死：

```

      单元本身的状态照写（`unfurnished`、`vacant possession`）——那是房子的事，不是业主的事
```

### 长版 — 自己网站、落地页、小红书、客户群

- **250–400 词**，可以写成段落而不是 bullet，可以加生活场景（早上怎么去地铁、周末在哪买菜），但**事实边界和标准版一模一样**
- 场景只能建立在已有事实上：「楼下就是 FairPrice」→ 可以写「买菜不用开车」；资料没说有超市 → 一个字不许有
- 要发小红书的再出一版中文：中文版不许出现「学区房」「稳赚」「保值」「一定升值」，**不许放电话、微信号、二维码**（平台规矩），也不许写单元号
- 长版可以放 1–2 个 emoji，中文版可以分小标题，但形容词密度还是要压住
- **这两版都没有平台代印的中介信息块**，所以持证中介的长版和长版·中文，结尾必须按「执业信息按渠道」那张附表挂上：姓名 + Salesperson Registration Number + 经纪行名称 + Estate Agent Licence Number + CEA 登记电话。固定写法：

```
{姓名} - {经纪行名称}
CEA Salesperson Registration No. {Rxxxxxxx} - Estate Agent Licence No. {Lxxxxxxx}
{CEA 登记电话}
```

  小红书那版同样挂这四项，但**电话那一行不放**（平台规矩）；用户坚持要留电话入口的，告诉他这版就别发小红书。业主自挂不需要这一段。

## 输出格式

写到工作目录 `房源文案/{项目名}-{卖或租}-{日期}.md`，六节，顺序固定：

**1. 各版本正文** — 每版一个代码块，块内就是纯可粘贴文本（不含任何说明文字），块前一行小标题写用途和长度。挂 2 个以上平台时标准版出 A/B，只挂 1 个就只出一个标准版、把「（平台名）」去掉：
```
### Headline（PG / 99.co 标题栏位）· 61 字符
### 短转发句（WhatsApp / 客户群）· 41 词
### 标准版 A（PropertyGuru 主 description）· 164 词
### 标准版 B（99.co 主 description）· 154 词      ← 只在挂 2 个以上平台时出
### 长版（自己网站 / 落地页）· 300 词（含末尾落款三行）
### 长版·中文（小红书 / 客户群，仅在用户要时出）· 约 320 字
```
Headline 那一行必须标字符数，并说明有没有过 10–70 和字符集这两条（见第 4 步）。

**2. 资料对照表** — 四列，一行一句，让用户 30 秒过完：

| # | description 里这句 | 出处 | 要不要你再确认 |
|---|---|---|---|
| 1 | `1,109 sqft strata` | 资料第 3 行 | 否 |
| 2 | `S$1,695 psf` | 我算的：1,880,000 ÷ 1,109 | 否 |
| 3 | `7 mins' walk to Kembangan MRT` | 资料第 8 行，你自己走过 | 否 |
| 4 | `maintenance fee S$450/mth` | 你口头说的，资料里没有 | **是** —— 第 6 节的门禁会因为这一行拦住交付 |

第四列只有两个值，没有中间态：

- **否** = 出处指得回资料某一行（或你量过、你确认过）。这才是可以直接粘的状态
- **是** = 这条我没有可靠出处，或者你自己说要再核。**只要有一个「是」，第 6 节的门禁就拦下整份交付**，所有版本标上 `【待确认，先别粘】`

所以「先填上去、写一句你核一下」不是一个选项。要么指得回出处，要么这句话不进正文——凭记忆填的 MRT 线路代号、District 编号、TOP 年份都是这一类。

**3. 还缺的 / 要你确认的** — 编号列表，每条写「缺什么 → 我现在怎么处理的 → 补齐了我加哪一段」。没写进去的东西必须在这里现身，不能悄悄消失。

**4. 钱和税的数字** — 逐条列：数字 → 出处 → 截至日期。结尾固定一句：
> 报价和租金以你提供的为准（截至 {日期}）。税率、印花税、物业费的规则会变，要往文案里写数字之前对一眼官网。

**5. 平台备注** — 表格：`平台 | 用哪一版 | HOOK 换成什么切入点 | 注意`。要挂几个平台就几行。

**6. 自检结果** — 逐条打勾，不是打勾就要说明。**联系方式和 CEA 那两条按渠道分开判**，因为平台版和自有渠道版的要求正好相反：

先是全部版本都要过的：
```
[ ] 归属确认过：用户答过「这套房是我自己在挂的」（这一套，不是上一套）
[ ] 每句都能指回资料某一行
[ ] 对照表第四列「要不要你再确认」一行「是」都没有
[ ] 没有凭记忆填的 MRT 线路代号 / District 编号 / TOP 年份
[ ] 没有 guaranteed / 回报承诺 / en-bloc 预测
[ ] 没有歧视字眼
[ ] 没有单元号、门牌号
[ ] 业主个人信息：没有姓名、没有性别（he / she / 他）、没有处境（自住 / 搬走 / 家具带走 / 为什么卖），引述已拿到业主同意
[ ] 数字重算过一遍：psf、步行分钟、面积、报价
[ ] 学校只在量过的情况下出现
[ ] 没有押金 / 租期条款 / 佣金 / 合同条件
[ ] Headline：10–70 字符、只用允许字符集（`·` 不在内）、连续标点 ≤2、连续数字 ≤6 位、没全大写
```

平台版（PropertyGuru / 99.co）额外两条：
```
[ ] 正文没有电话 / 微信 / 邮箱 / 外部链接 / 其他平台名
[ ] 正文没有 CEA 号和中介姓名（平台的中介信息块已经印了）
```

自有渠道版（自己网站 / 落地页 / 小红书 / 客户群）额外两条：
```
[ ] 结尾四项齐：中介姓名 / Salesperson Registration Number / 经纪行名称 / Estate Agent Licence Number（+ CEA 登记电话，小红书版不放电话）
[ ] 小红书版：没有电话、微信号、二维码
```

**两条硬门禁，过不了就不算交付：**

1. **对照表第四列还有任何一行是「是」** → 所有版本都在标题上标 `【待确认，先别粘】`，把卡住的是哪几行写出来，**等用户逐行点头才算交付**。同时把那条事实在正文里换成不带代号／不带数字的写法（例：`7 mins' walk to Kembangan MRT`，不写 `(EW6)`）。
2. **归属那条没确认** → 走 B 线，只出收料清单和骨架，不出可粘贴正文。

## 不许写的话

| 不许写 | 为什么 | 改成什么 |
|---|---|---|
| `guaranteed` / `guaranteed rental yield` / `assured returns` / 「稳赚」「保值增值」「肯定涨」「回报 X%」 | CEA 广告规矩最直接的雷，也是投诉素材 | 删。要摆投资角度就只写报价、面积、psf 这些可核实的数字 |
| `en-bloc potential` / `sure en-bloc` / `redevelopment upside` | 预测，没法核实 | 删，连 `potential` 都别带 |
| 「学区房」/ `school district` / `guaranteed placement` / `priority admission` | 新加坡是 1 公里内优先抽签，不是学区制 | `within 1 km of {学校名} Primary School`，距离必须自己量过 |
| `best deal in the market` / `below valuation` / `must sell` / `owner relocating urgently` | 无法核实，还暴露业主处境、削弱谈判位置 | 删 |
| `rare` / `only one in the project` / `last unit` | 指不出出处 | 删，除非真能说清是什么口径 |
| `no Indian` / `no PRC` / `Chinese family preferred` / `suitable for local family only` / 任何国籍宗教家庭结构的筛选 | 歧视，租盘高发 | 一个字都不能有。租客筛选是业主在看房和 TA 阶段自己做 |
| 电话 / WhatsApp / 微信号 / 邮箱 / 外部链接 / 其他平台名，**写进 PG / 99.co 的正文** | 平台会退回或降权，电话还会被 mask 掉 | 平台版删掉，联系方式走挂盘页的固定栏位。自己网站 / 落地页那版可以放 |
| 中介姓名 + CEA 注册号写进 **PG / 99.co** 正文 | 平台的中介信息块已经印了，重复只占字数 | 那两版正文不写。**自己网站 / 落地页 / 小红书 / 客户群反过来：必须挂姓名 + 注册号 + 经纪行 + 执照号**，见「执业信息按渠道」那张附表 |
| 单元号 / 门牌号 / 业主姓名 / 业主性别（he / she / 他）/ 业主自住或搬走 / 家具带走 / 业主为什么卖 | 房源广告带着地址，业主就是可识别的个人；这些属性和处境是他的个人资料，发到公开渠道要他同意，而且削弱他的谈判位置 | 只写路名或「off {某条路}」；业主统一只以 `the owner` 出现，处境一个字不写 |
| 业主的原话，**没问过他同不同意公开** | 同上，属于把客户个人资料带到公开渠道 | 先问「这句可以写进公开挂牌文案吗」，答复和日期记进「还缺的」；没同意就整句删，不许改成「据说」 |
| MRT 线路代号（`(EW6)` 这类）/ District 编号，用户资料里没给 | 本 skill 不联网，填进去的只能是凭记忆猜的；冷门站和跨区地段猜错就是广告里的事实错误 | 只写站名，不带括号；District 一节整段删，列进「还缺的」让他自己核 |
| 猜的房龄、面积、朝向、楼层、layout | 编造，业主和买家一看就知道 | 照资料抄；资料没有就整篇不提 |
| 「装修大概 2020 左右」/ `recently renovated`（不知道哪年） | 模糊等于编，被问就露 | 要么写准确年份，要么只写 `renovated` 不带年份 |
| 押金、租期条款、佣金、交易条件的具体条款 | 那是 TA / LOI / 合同的事，本 skill 不碰 | 最多写业主明确说过的偏好（`min 2-year lease preferred`） |
| 税率、印花税金额、月供、回报率 | 会变，写错比不写糟 | description 里不写。要算另开一条；非写不可就标出处和截至日期，并提醒对一眼官网 |
| 整段全大写、连串叹号、一排 emoji | 看着像群发，平台和买家都反感 | 只有分段小标题可以大写，标准版不放 emoji |

## 中介场景：同一个盘挂多平台，怎么换措辞

一套房挂 PropertyGuru + 99.co + 自己网站是常态。三处放同一段字，两个后果：平台自己的查重会压掉后来那条的排序；同平台重复挂牌还可能直接下架。

**变三样，绝不变两样。**

不变（这条比什么都重要）：
1. **所有事实一个字不改**——面积、报价、房型、楼层段、朝向、租约状态、MRT 分钟数、学校距离。为了「看起来不一样」把 `mid floor` 在另一个平台写成 `high floor`，那不是换措辞，那是编。
2. **红线和「不许写的话」在每个平台都一样**，不因为「自己网站没人管」就放松。

变：
1. **HOOK 换切入点**——同一套房有三四个卖点，一个平台主打一个
2. **段落和 bullet 顺序换**——LOCATION 放前面还是 UNIT 放前面
3. **同义词轮换**——见下表

| 意思 | 可轮换的说法 |
|---|---|
| 走得到地铁 | `7 mins' walk to X MRT` / `a short walk from X MRT` / `X MRT is about 7 mins on foot` |
| 采光好 | `bright` / `sunny` / `plenty of natural light` |
| 维护得好 | `well-maintained` / `kept in good condition` / `the development is well looked after` |
| 拎包入住 | `move-in ready` / `ready for immediate occupation` / `you can move straight in` |
| 装修过 | `renovated in 2023` / `kitchen and flooring redone in 2023` / `updated in 2023` |

**这张表是换说法的，不是拿素材的。** 轮换的前提是那条事实本来就有据。资料没说小区维护得好，`well-maintained` 那一行三种说法一种都不能用——这是最容易在「换措辞」的名义下犯的编造。

推荐分工：

| 平台 | 用哪一版 | HOOK 切入点 | 注意 |
|---|---|---|---|
| PropertyGuru | headline 进标题栏，标准版 A 进 description 栏（后台就这两个文本栏位） | 通勤 + 房型面积 | headline 按 10–70 字符和字符集那套规则核过；正文不放联系方式、不放 CEA 号（平台的中介块已经印了） |
| 99.co | headline 进标题栏，标准版 B 进 description 栏（换 HOOK、换段落顺序、轮换同义词） | 小区设施 + 装修状态 | 事实必须和 PG 那版逐条一致；同上不放联系方式和 CEA 号 |
| 自己网站 / 落地页 | 长版 | 生活场景 | 没有平台代印的中介块，所以**结尾必须挂四项**：姓名 + Salesperson Registration No. + 经纪行名称 + Estate Agent Licence No.（+ CEA 登记电话）。联系方式这里可以放，平台上不行 |
| 小红书 | 长版·中文 | 生活场景 + 价格带 | 同样**结尾挂那四项**（电话那行不放）；不放微信号、二维码；不写「学区房」「稳赚」 |
| 客户群 / 转发 | 短转发句 + 标准版首段 | 最强卖点 | 持证中介发的同样挂那四项；不带其他中介信息；给第三方看的截图里别人的挂牌信息要剥掉 |

业主自挂 / 房东自挂：上面三行「挂四项」的要求不适用，他不是持证中介。

**同一套房在同一个平台只能有一条 listing**，同房源重复挂会被下架。价格调整就改那一行数字，不要重写整段——各版都存档在 `房源文案/` 里，改价只动报价和 psf 两处。

## 常见卡点

1. **现象**：写出来全是形容词，读完不知道这套房长什么样。
   **原因**：资料只给了项目名和报价，楼层、朝向、装修、家具四项全空，只能用形容词填。
   **怎么解**：回第 0 步把那四项一次问齐。用户真不知道就只出 headline + 短转发句交付，并在「还缺的」里写清楚为什么短——用形容词凑长度是在给自己埋投诉。

2. **现象**：用户说「标题框放不下 / 后台说标题不合规 / 粘进去被退回来了」。
   **原因**：把标准版或短转发句塞进了 headline 栏位——那栏只有 10–70 字符；或者标题里用了 `·`（不在 PG 允许的字符集里）、用了 `S$1,880,000`（连续数字超过 6 位）、整句全大写。
   **怎么解**：headline 用第 4 步那套规则重写一条，数一遍字符数；分隔符换成 `-`，价格写 `S$1.88M`。description 栏位放标准版。bullet 符号用 `-` 不用 `•`；粘完在平台自己的预览里看一眼再保存。

3. **现象**：description 被平台退回、下架或流量特别差。
   **原因**：PG / 99.co 的正文里塞了联系方式、外部链接、别的平台名，或者整段全大写加一串叹号；也可能是同一段字在两个平台一模一样被判重复。
   **怎么解**：按「自检结果」的平台版那几条过一遍，删掉联系方式和链接（**注意只删平台版那两版，自己网站和小红书那两版的姓名 + CEA 注册号 + 经纪行 + 执照号是必须留的**）；重复问题按「中介场景」那节换 HOOK、换顺序、换同义词，**事实一个字不改**。

4. **现象**：业主或买家来说「你写的朝向不对 / 面积不对 / 哪来的两个卫生间」。
   **原因**：单元级信息不是从资料抄的，是从房型面积推的，或者从记忆里别的单元串过来了。
   **怎么解**：对照表里每一行都要指得出出处，指不出的当场删。事后要认，改完重发一版，不要辩。这一条犯一次就够赔掉信任。

5. **现象**：用户要求「顺便把印花税算一下」「加一句回报率」。
   **原因**：把挂牌文案当算账工具。
   **怎么解**：description 里不写税率和回报率（红线 3、7）。要算就另开一条（算账那条 skill），算出来的数字标出处和截至日期，并且提醒「税率和规则会变，用之前对一眼官网」；算完也不塞回 description。

6. **现象**：用户说「帮我直接挂上去 / 帮我发给这几个客户」。
   **原因**：以为这条 skill 能操作平台或发消息。
   **怎么解**：本 skill 只出草稿。告诉他：各版已经写好在 `房源文案/` 里，复制粘贴到他自己的 PropertyGuru / 99.co 后台，发布按钮他自己按；发客户也是他自己在自己的 App 里发。不生成任何发送链接，不代点任何按钮。

7. **现象**：用户贴来一份资料，问到归属时说「同事的盘」「客户群里转来的」「PG 上看到的，我照这个改一版」。
   **原因**：以为这条 skill 是改写工具。
   **怎么解**：走 B 线——只给他「要问业主哪几项」的收料清单和骨架，不出可粘贴正文。原因说一遍：没有 marketing authority 的人做房源广告，CEA 那边是越界；照着别家中介的挂牌文案改写，也是拿人家花钱写的东西。要出文案就两条路：让挂盘那位自己跑这条 skill，或者把业主的授权书拿到手再回来。

8. **现象**：用户说「我发在自己网站上，为什么你这版尾巴挂了一串 CEA 号，PG 那版又没有」。
   **原因**：以为「正文不写 CEA 号」是全局规矩。它只对 PG / 99.co 成立，因为那两个平台自己会印中介信息块。
   **怎么解**：按「执业信息按渠道」那张附表解释一遍：自己网站、落地页、小红书、朋友圈没有那个块，CEA 广告规矩要的姓名 + 注册号 + 经纪行 + 执照号得跟着文案走。他嫌长可以排成一行小字，但不能删。
